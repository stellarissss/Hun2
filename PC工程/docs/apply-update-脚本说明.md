# 更新包安装脚本（apply-update.bat）技术说明

> 面向维护者。说明 `apply-update.bat` 的搜索策略、设计约束与验证方式。
>
> 该脚本由 `scripts/make_overlay.py` 的 `BAT_TEMPLATE` 统一生成，
> 编码为 **GBK**（批处理对中文路径的要求），随每个更新包一同发布。

---

## 一、它要解决的问题

早期版本的安装脚本只做两件事：看自己所在目录、再看上一层，找 `混在日本.exe`。
这在实际使用中会失效：

| 失效场景 | 原因 |
|---|---|
| 更新包解压到仓库的深层目录 | 只向上找一层找不到游戏 |
| 游戏在其它盘 / 其它分支 | 完全没有全盘搜索能力 |
| 用的是便携版 | 便携版主程序名不是 `混在日本.exe` |
| 游戏中/英文路径含空格、括号 | 未做引号与转义处理 |

---

## 二、搜索策略

脚本从更新包所在目录出发，按以下顺序收集候选目录：

```
1. :scan         更新包目录自身 + 向下递归 4 层
2. :scan_parents 向上逐级（最多 5 级），每级做一次完整递归
                 → 到达盘符根时转交 :scan_drive
3. :scan_root    所在磁盘的常见安装位置
                 （Games / 游戏 / Program Files / Program Files (x86) /
                   hun / 混在日本 / Apps / Software / Steam\steamapps\common）
4. :scan_drive   盘符根 + 向下 2 层
```

命中结果写入候选表 `%TEMP%\hun_update_cands.txt`，`:add` 逐行精确比对去重。

### 判定依据（`:verify`）

只要满足以下任一特征即认定为游戏目录：

- `<dir>\混在日本.exe` —— 安装版主程序
- `<dir>\混在日本-便携版-*.exe` —— 便携版主程序
- `<dir>\resources\app.asar` —— Electron 打包标志
- `<dir>\resources\app\package.json` —— 未打包形态

**更新包自身及其所有子目录被强制排除**（前缀匹配 `PKGDIR`）。
否则更新包里的 `app_overlay` 会让脚本把「自己」认成游戏，造成自我覆盖。

## 三、分支行为

| 候选数 | 行为 |
|---|---|
| **0** | 提示手动输入路径；并告知可直接把 `app_overlay` 拖进游戏目录 |
| **1** | 直接安装 |
| **≥2** | 编号列出，输入序号选择；同时提供「0. 手动输入路径」 |

安装流程：校验目录 → 检查进程占用 → 解析 `version.json` 取版本号 →
备份旧 `app_overlay` 为 `app_overlay.bak` → `xcopy /E /I /Y /Q` →
校验 `app_overlay\www\index.html` 存在 → 输出结果与回退方法。

### 退出码

| 码 | 含义 |
|---|---|
| `0` | 安装成功 |
| `1` | 未完成（用户放弃、校验失败、复制失败等） |

## 四、批处理陷阱与相应对策

中文 Windows 批处理有几个著名坑，脚本逐条做了规避。**这些坑在 Wine 下测试时全部被复现过。**

| 陷阱 | 现象 | 对策 |
|---|---|---|
| **块内用 `%var%`** | 若变量值含 `(` `)`（如 `Program Files (x86)`），括号会被当作块定界符，报 `Can't recognize 'x86'` | 所有位于 `(...)` 块内的路径一律用 `!var!` 延迟展开 |
| **`for /d` + 引号通配** | 部分环境下 `for /d %%D in ("path\*")` 返回空集 | 改用 `for /f` + `dir /b /ad "path"` 枚举子目录 |
| **`if exist "C:\"`** | 盘符根在某些环境被当作「当前目录」而误判不存在 | 改用 `dir /b /ad "C:\"` 的退出码探测 |
| **`for %%D in ("path\..")`** | 不可靠，且可能触发文件迭代副作用 | 自写 `:up` 子过程，逐字符定位最后一个 `\` 截断 |
| **尾随 `\` 紧贴 `)`** | `if exist "x\"` 中的 `\"` 被当作转义引号 | 先赋值给变量再引用，或统一归一化路径 |

### 关键子过程

| 过程 | 作用 |
|---|---|
| `:verify` | 判断目录是否为游戏目录，返回 `VERIFYOK` |
| `:scan` | 递归扫描（4 层），盘符入参自动转 `:scan_drive` |
| `:scan_parents` | 逐级向上，每级整树递归 |
| `:scan_root` | 扫常见安装位置 |
| `:scan_drive` | 盘符根 + 2 层 |
| `:add` | 去重追加候选 |
| `:up` | 取上一级目录（逐字符实现） |
| `:is_drive` | 判断入参是否为 `X:` 形式 |
| `:startswith` / `:strlen` | 前缀匹配与长度（用于排除更新包目录） |

## 五、验证方式

脚本逻辑曾在 **Wine 环境**下真机执行验证。由于 Wine 的 C 运行时无法正确解析
中文路径（`%~dp0` 会把中文段变成 `??????`），路径相关用例使用等价的 ASCII 目录名，
代码分支完全一致。

覆盖的五类场景：

| # | 场景 | 期望 | 结果 |
|---|---|---|---|
| 1 | 仓库深层嵌套（更新包与游戏相隔 3 层） | 自动找到并安装 | ✅ |
| 2 | 更新包与游戏同级（游戏在其上一级子目录） | 自动找到并安装 | ✅ |
| 3 | 存在多个游戏目录 | 列出候选，按序号选择 | ✅ 选 2 正确，未误改另一个 |
| 4 | 完全找不到游戏 | 放弃（exit 1）并引导手动输入 | ✅ |
| 5 | 游戏在盘根同级（跨 4 层） | 逐级向上至盘根后找到 | ✅ |

另验证：手动输入非游戏目录会被拒绝；更新包目录不会自我覆盖；
安装后 `app_overlay\www\index.html` 与 `version.json` 均就位，版本号正确。

> Wine 无法覆盖的部分：中文路径的真实解析、`tasklist` 进程检测、
> `xcopy` 的权限行为。这些依赖真实 Windows，需在目标机上人工确认一次。

## 六、维护提示

- **脚本与版本号解耦**：自动扫描 `*.part00`、自动从 `version.json` 读版本，
  升级时**不需要改这个文件**。
- 修改 `BAT_TEMPLATE` 后，务必：
  1. 确认整段文本可用 **GBK 编码**（不能含 GBK 之外的字符）；
  2. 确认不含三引号 `"""`（会破坏 Python 原始字符串）；
  3. 重新跑一遍上述五类场景。
- 若新增识别特征，记得同步更新 `:verify` 与本文档。
